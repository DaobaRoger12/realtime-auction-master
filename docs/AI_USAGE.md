# AI 全栈应用说明

本课题在两个层面应用 AI：**① AI 辅助编码**（开发过程）与 **② 产品内嵌 AI 能力**（豆包 Doubao-Seed-2.0-lite）。本文沉淀使用思路、流程与贡献度评估 —— 不追求「AI 代码占比越高越好」，而强调**关键决策点的人工把控**与**生成代码的规范、可复用、可追溯**。

---

## 一、产品内嵌 AI 能力（豆包 Doubao-Seed-2.0-lite / 火山方舟）

通过 OpenAI 兼容协议接入，封装在 [services/aiService.ts](../packages/server/src/services/aiService.ts)，对外暴露两个能力：

### 1. AI 商品文案 + 智能规则推荐 `POST /api/ai/describe`
商家在「发布竞拍」页填入商品名与品类，点「✨ AI 生成」：
- 模型据品类（珠宝/艺术品/二手奢侈品…）生成 **24 字内标题 + 120~200 字卖点文案**（材质/工艺/稀缺性/场景）；
- 同时**推荐竞拍规则**（起拍价/加价幅度/封顶价/时长），自动回填表单，商家可微调。
- 让经验不足的商家也能快速产出专业的竞拍配置，降低冷启动门槛。

### 2. AI 实时拍卖师话术 `POST /api/ai/commentary`
直播间根据场景（开场 / 出价 / 临近结束 / 成交）实时请求一句拍卖师话术，注入商品名、当前价、参与人数等上下文，营造「家人们注意啦，0 元起拍速来出价！」式的真实竞价氛围。

### 工程化保障
- **超时控制**：`AbortController` 12s 超时，不阻塞主链路。
- **模板兜底**：KEY 失效 / 网络异常 / JSON 解析失败时，自动回退到内置模板，保证接口**永远返回可用内容**，演示与生产都不被第三方拖垮。
- **可追溯**：所有 AI 调用经统一 `chat()` 入口，参数与异常落日志。
- **安全**：API Key 仅存于 `.env`（gitignore），不入源码、不外泄。

## 二、AI 辅助编码（开发流程沉淀）

### 使用的 AI 工具
- **Claude Code**（Anthropic 官方 CLI）作为主力编码 Agent，完成脚手架、样板代码、组件、测试脚本的生成与重构。

### 方法论：架构先行，AI 提速，人工定夺关键决策
1. **人工定架构**：技术选型（Fastify + ws + MySQL + Redis）、分层（shared / repositories / services / ws / routes）、一致性方案（分布式锁 + 乐观锁 + 唯一键三重防线）、状态机设计 —— 这些**核心决策由人把控**，AI 负责落地。
2. **契约驱动**：先用 AI 搭好 `shared` 共享类型/事件/规则纯函数，作为前后端契约，再并行生成两端代码，避免接口漂移。
3. **生成—验证闭环**：每完成一层即用 `tsc` 类型检查 + 真实运行验证（冒烟脚本 `smoke-ws.mjs`、压测脚本 `loadtest.ts`），用**实测数据**驱动优化（如发现 presence O(N²) 风暴 → 人工提出合并节流方案 → AI 实现 → 复测 219ms→18ms）。
4. **关键逻辑人工评审**：出价幂等、乐观锁回滚、防狙击延时、结算事务边界等**正确性敏感**代码，逐行人工复核，不盲信生成结果。

### AI 代码贡献度（评估）
- 样板/脚手架/UI 组件/类型定义：AI 贡献度高，规范统一、可复用。
- 核心业务逻辑（出价管线、状态机、一致性方案、并发优化）：AI 提供初稿，**关键决策与正确性由人主导**，属于「人机协同」。
- 合理性自评：贡献率高的部分恰是重复度高、易出错少的样板；而决定系统成败的并发一致性与规则正确性，把控权始终在人 —— 这正是题目强调的「关键决策点的人工把控」。

### 可追溯性
- Monorepo 分层清晰、注释完整，每个核心模块顶部有职责说明；
- 压测/冒烟脚本可一键复现实测结论；
- 本文与 [ARCHITECTURE.md](./ARCHITECTURE.md) 记录了关键技术决策的「为什么」。
