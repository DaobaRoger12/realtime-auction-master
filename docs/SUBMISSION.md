## 4. 核心功能清单
1. **商家 AI 发布竞拍**：上传商品，点「✨AI 生成」由豆包自动产出卖点文案 + 推荐规则；配置 0 元起拍、加价幅度、封顶价、时长、防狙击延时。
2. **实时多人竞价**：WebSocket 长连接，毫秒级同步当前价/排行榜/倒计时；一键加价、自定义档位、封顶一口价。
3. **复杂规则引擎**：0 元起拍 / 按幅度递增 / 封顶自动成交 / 临近结束自动延时 / 主播取消异常竞拍，状态机零漏洞。
4. **竞价氛围体验**：「🎉领先 / ⚡被超越 / ⏱️延时」动画+音效、实时排行榜重排、紧张倒计时、AI 拍卖师话术。
5. **成交与订单**：达成交自动生成订单，用户模拟支付，查看历史竞拍记录；商家侧订单管理 + 实时监播。
6. **高并发与一致性**：分布式锁 + 乐观锁 + DB 唯一键三重防线，杜绝一笔出价扣两次钱；单直播间 1000+ 在线。

## 5. 端到端使用流程
1. 商家登录管理后台，在「发布竞拍」填写商品名与品类，点击「AI 生成」自动获得文案与推荐规则。
2. 商家微调起拍价/加价幅度/封顶价/时长/延时后发布，竞拍立即开拍（或定时开拍）。
3. 用户打开移动端直播间，看到直播画面、当前价、毫秒倒计时、在线人数与实时排行榜。
4. 多名用户出价，每次出价秒级广播到全场，领先者获「🎉领先」反馈，被超越者获「⚡被超越」提醒，排行榜实时重排。
5. 临近结束时有人出价则触发「⏱️自动延时」，倒计时延长；出价达到封顶价则立即成交。
6. 竞拍结束弹出结果页，中标用户「💳模拟支付」生成订单，可在「我的竞拍记录」查看。
7. 商家在后台「实时监播」页同步看到出价流、排行榜、在线人数，并可一键「取消异常竞拍」。
8. 全程数据一致：并发抢拍下系统只接受合法且严格递增的出价，其余精确拒绝，绝无重复成交。

## 11. 大模型 / AI 能力使用说明
- **使用模型**：字节火山方舟 **Doubao-Seed-2.0-lite**（OpenAI 兼容 Chat Completions 协议，Endpoint `ep-...`）。
- **接入位置**：后端 `services/aiService.ts` 统一封装，REST 暴露 `POST /api/ai/describe`、`POST /api/ai/commentary`、`GET /api/ai/status`。
- **能力一**：商品文案 + 智能规则推荐 —— 商家发布页一键生成 24 字标题 + 120~200 字卖点 + 推荐起拍/加价/封顶/时长。
- **能力二**：实时拍卖师话术 —— 直播间按场景（开场/出价/临近结束/成交）注入商品/价格/人数上下文，生成一句催价话术。
- **Prompt 方案**：System 设定「资深直播运营/金牌拍卖师」角色 + 强约束输出（describe 要求只返回 JSON；commentary 限 40 字一句话）；详见 AI_USAGE.md。
- **工程化**：`AbortController` 12s 超时 + **全链路模板兜底**（KEY 失效/超时/JSON 解析失败自动回退），保证接口永远可用；调用统一入口、可追溯；API Key 仅存 `.env`（gitignore）。
- 未使用向量库/RAG（本课题为强实时交易场景，AI 用于内容生成而非检索问答）。开发侧用 **Claude Code** 作为编码 Agent（方法论见 AI_USAGE.md）。

## 12. 关键工程难点与解决方案
**难点一：高并发出价的数据一致性（绝不重复扣款/排名错乱）**
- 方案：**三重防线** —— ① Redis 分布式锁（带 token + Lua 安全释放）将同一竞拍出价串行化；② MySQL 乐观锁 `UPDATE ... WHERE version=?` 兜底并发写；③ `bids(auction_id, request_id)` 唯一键做幂等终防线。压测中 10 机器人疯抢，系统只接受严格递增的合法出价，其余精确拒绝。

**难点二：单直播间 1000+ 在线的广播风暴**
- 现象：每个用户进房即广播在线数，1000 人建连产生 O(N²)≈50 万条消息，延迟升至 219ms。
- 方案：按房间对 presence 广播做**合并节流**（≤2.5 次/秒），O(N²)→O(N)。实测延迟 **219ms→18ms**、广播量 **85万→7.8万**、建连速率 65→644/s。

**难点三：毫秒级倒计时跨端一致**
- 方案：每条 WS 下行带服务器 `ts`，结合 welcome/pong 的 serverTime 与 RTT/2 估算时钟偏移，前端 `serverNow()` + requestAnimationFrame 渲染，避免各端本地时钟漂移导致结束时间不一致。

**难点四：WebSocket 弱网稳定性**
- 方案：心跳 ping/pong + 超时清理；客户端**指数退避 + 抖动重连**，重连后自动重新 join 房间并拉取最新快照，无缝恢复；服务重启从 DB 恢复 LIVE 场次定时器与排行榜（重启不丢拍）。

## 13. 项目亮点 / 创新点
1. **三重防线的出价幂等与一致性**（分布式锁 + 乐观锁 version + DB 唯一键），任一层失效都不破坏正确性 —— 直面课题「绝不允许一笔出价扣两次钱」红线。
2. **presence 合并节流把广播复杂度 O(N²)→O(N)**，配合 Redis Pub/Sub 房间级隔离，单机实测 1000 并发 0 失败、18ms 延迟，且天然水平可扩展。
3. **沉浸式竞价氛围 + AI 拍卖师**：领先/被超越/延时的动画与音效、排行榜布局动画、毫秒紧张倒计时，叠加豆包实时话术，把"紧张刺激"做到极致。

### 14.2 Prompt 策略 / 失败兜底
- **describe**（文案+规则）：System=资深直播运营；User 给定商品名/品类/关键词，强制只输出 JSON（title/description/起拍价/加价/封顶/时长）；解析失败→内置模板。
- **commentary**（话术）：System=金牌拍卖师，限一句≤40字；注入「商品/当前价/出价次数/参与人数」上下文；异常→分场景模板兜底。
- 兜底机制保证「第三方不可用也不拖垮主链路」。

### 14.3 评测方案与样例
- **冒烟脚本** `smoke-ws.mjs`：双买家竞价，验证 领先/被超越/BELOW_MIN/限流/幂等/并发只一人成功。样例输出：
  ```
  [阿哲] ✅ 出价被接受: ¥100 领先者=2  榜首=收藏家阿哲
  [小美] ✅ 出价被接受: ¥200 领先者=3  榜首=珠宝控小美   ← 超越
  [阿哲] ❌ 出价被拒: BELOW_MIN  最低应价=30000
  [并发] 两人同抢同价 → 一人 ✅ / 一人 ❌ BELOW_MIN     ← 一致性
  ```
- **AI 样例**：输入「天然缅甸翡翠满绿手镯/珠宝」，commentary 输出「家人们注意啦！天然缅甸满绿翡翠手镯0元起拍，想捡漏的赶紧出价别手软！」
